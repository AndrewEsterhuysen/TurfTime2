## 2. Problems Addressed This Session

### 2.1 Drag 'n Drop Unresponsive
- Long-press delay was too high; drag detection was unreliable.
- Fixed by moving touch arbitration into `Platforms/Android/DragLayoutViewGroup.cs`.
- Reduced long-press timer from 350 ms → 300 ms.
- Added haptic feedback (`PerformHapticFeedback(FeedbackConstants.LongPress)`) on confirmation.
- Introduced `DragState.LongPressConfirmed` as a shared bridge between native and managed layers.

### 2.2 Scroll vs Drag Conflict
- Scrolling the roster triggered drag-and-drop on the row under the finger.
- Resolved inside `DragLayoutViewGroup.DispatchTouchEvent`: scroll is allowed until the long-press timer fires; only then does the parent intercept get locked.

### 2.3 Swipe Jitter & Animation Smoothness
- Post-gesture `GameViewModel` refreshes (`MarkNextPlayers`, `RefreshRotationPairs`, `RefreshDisplayItems`) were running synchronously on the gesture path, causing frame skips.
- `CommitSwipe(...)` in `GamePage.xaml.cs` was changed to start the bounce animation first and defer `SetPlayerPosition(...)` to the dispatcher.
- Reorder now uses `ObservableCollection.Move()` instead of remove/insert to minimise collection-change churn.

### 2.4 Drag-Active Visual Cue
- Added `IsDragging` property to `Player.cs`.
- The active drag row now dims its border opacity and the `☰` handle turns orange and enlarges.
- Driven by `DataTrigger` in `GamePage.xaml` using MAUI-compatible `{x:Boolean True}` syntax.
- `BoolToOpacityConverter` added to `Converters/GameConverters.cs` for the insertion-marker indicator.

### 2.5 Log Feature Removed; Reports Retained
- The Log menu item and all log-specific code were deleted.
- Report menu and report code were preserved.
- Confirmed no shared code between the two features before removal.

### 2.6 Table View Deleted
- `TeamViewMode.Table` was removed; only `Swipeable = 0` and `Rotation = 1` remain.
- Related persisted-mode handling was updated throughout.

### 2.7 Local Team — Chat & Cloud Suppression
- When a team is stored locally (`isLocalTeam == true`), the Chat menu option is now hidden.
- All cloud warm-up and cloud-related calls are suppressed to prevent pointless error logs.

### 2.8 Game Page Header Rebuilt
- Replaced old layout with a four-row design matching the original WebView look:
  1. `⚽ Turf Timer 🥅`
  2. Team name
  3. Label row: `Us | Match Time | Rotate | Them`
  4. Score/timer row: Us score | match timer | rotate timer | Them score

### 2.9 Rotation Page Layout
- Below "Next Rotation": bench player name (left-aligned) on one line, field player name (right-aligned) on the next, repeated for all rotation pairs — matching the old WebView layout.

## 4. Bug Fixed: Swipe Stops Halfway (Player 2)

### Symptom
Swiping Player 2 to the left caused the row to stop mid-animation and never return to centre.

### Root Cause
`PanGestureRecognizer.Completed` is **not guaranteed** on Android when the finger leaves the view bounds during a fast swipe. The debug log showed:
- `✅ Started — player='Player 2'`
- `🎯 Intent decided: Swipe`
- Multiple `Finger slipped` messages from the native layer
- **No `🏁 Completed` event ever fired**

The row's `TranslationX` was left at its mid-swipe offset with no cleanup path executing.

### Fix (three-file change)

**`DragState.cs`**
```csharp
public static Action? NativeSwipeReleased;
```

**`DragLayoutViewGroup.cs`** — on `ACTION_UP/CANCEL`, when the gesture was not a confirmed drag:
```csharp
DragState.NativeSwipeReleased?.Invoke();
```

**`GamePage.xaml.cs`** — subscribe/unsubscribe in `OnAppearing`/`OnDisappearing`:
```csharp
DragState.NativeSwipeReleased += OnNativeSwipeReleased;
```
The handler is a **no-op** if `_panRow is null` (MAUI already delivered `Completed`). Otherwise it dispatches `CommitSwipe(...)` on the UI thread — snapping the row back or applying the position change identically to a normal completion.

### Idempotency Guard
```csharp
private void OnNativeSwipeReleased()
{
	if (_panRow is null) return; // MAUI already cleaned up — nothing to do
	...
	Dispatcher.Dispatch(() => { CommitSwipe(row, player!); ... });
}
```

## 6. Architecture Notes

- Native parent-intercept control (`DragLayoutViewGroup`) is intentionally separated from managed gesture intent (`GamePage.xaml.cs`). This is the correct design.
- `DragState` is the only shared bridge; keep it minimal.
- MAUI `PanGestureRecognizer` completion is unreliable on Android for fast gestures — always pair it with a native `ACTION_UP` fallback.
- Visual changes in row templates must not trigger layout invalidation to avoid jitter; use opacity toggling (`BoolToOpacityConverter`) rather than `IsVisible` for the drag insertion marker.
