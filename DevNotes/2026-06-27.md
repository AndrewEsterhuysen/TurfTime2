# Dev Notes - 2026-06-27

## iOS/.NET MAUI Runtime Stability (Simulator + Device)

### What helped resolve launch/runtime failures
- Hard clean build artifacts before iOS troubleshooting:
  - Delete `bin/` and `obj/`
  - Rebuild from scratch
- Keep Debug iOS runtime settings simulator-safe:
  - `MtouchUseLlvm=False`
  - `UseInterpreter=True`
  - `MtouchLink=None` (Debug only)
- Use valid SDK pinning in `global.json` to avoid silent toolchain drift.

### Preventative workflow for future sessions
1. Start with hard clean (`bin/` + `obj/`) before deeper debugging.
2. Rebuild iOS Debug and deploy to simulator.
3. If launch is unstable, reset simulator content/settings and reinstall app.
4. Change one runtime variable at a time (SDK/Xcode/simulator runtime/LLVM/linking).
5. Verify on physical device for final confidence (simulator-only issues can mislead).

### Notes from this session
- Crash signature pointed to early Mono runtime startup (`load_aot_module`) before app UI logic.
- QR feature code was not the root cause of startup crashes.
- `dotnet workload repair` may require elevated permissions in some environments.
